## What exists

What each milestone built:

|---|---|

| 2 | What the investigator and the evaluation read: the cut case evidence with its charts, a library of earlier postmortems extracted into sections and described figures, and the frozen answer keys |
| 3 | The library index in Azure AI Search, a search that a case can use only within its date bound and its picks, and the checks that prove both on the live index ([worklog](../worklogs/03-retrieval.md)) |

| 5, judging | The scored runs, the injection runs with the case-chart variant ([decision 0026](../decisions/0026-case-chart-injection.md)), the Foundry cloud evaluation, the judge's proposals, and the reviewer model's decisions on the review queue ([decision 0027](../decisions/0027-reviewer-model.md)), recorded; the scores and the Claude API spend from them ([report](../../eval/reconstruction/showcase-v1/README.md), [runbook](../runbooks/evaluation.md)) |

### What reaches the investigator

Three cuts decide what the investigator can read. The evidence cut follows [decision 0005](../decisions/0005-evidence-library-and-answer-key.md), the library follows [decision 0013](../decisions/0013-library-selection.md), and the answer keys stay with the evaluation.

![What the investigator can read: Three lanes. Case evidence: each case's status snapshot, read from Blob Storage and checked against its SHA-256, goes through the evidence cut, which keeps the updates before the resolved one and drops the resolved update's text and any report entries, and becomes the case evidence with its Radar chart descriptions. Library: each library page, picked by the case's symptoms, is cut to its article and extracted; a page must be dated before every case it serves, and later text and bylines are dropped; the result is the library extract, whose figures are not shown. Answer keys: each case's postmortem, which is never in the library, is drafted into a key, reviewed with every quote checked word for word and facts already stated during the incident marked, and frozen with its SHA-256. The investigator reads the case evidence and the library extract; the frozen keys are for the evaluation only. Every step fails closed: an unknown entry is dropped and listed, and a page without its date or a key with a missing field is refused.](../diagrams/extraction-flow.svg)

### Components

| Part | Where | What it does |
|---|---|---|
| Settings | `hindcast.config` | Reads endpoints and deployment names from `HINDCAST_*` variables, one section per component (models, storage, extraction, search, safety), and names every missing variable of that section at once. No keys. Each command loads only the sections it uses, so a command that does not search needs no search values. |
| Capture | `hindcast.capture` | `status` takes one incident from a provider's status API as canonical JSON (Cloudflare and GitHub by incident ID; Google Cloud from its feed or a saved copy of it). `page` saves a postmortem page as served. Both refuse to overwrite a file, fetch only `https` URLs, and print the registry lines: URL, retrieval time, SHA-256. |
| Case registry | `data/cases.yaml`, `hindcast.cases` | Ten outages: four scored showcase cases, one development case, and five sealed cases, each with its start time, and four injection copies of the development case ([decisions 0025](../decisions/0025-injection-test-layers.md) and [0026](../decisions/0026-case-chart-injection.md)). Each has its status updates (evidence), from one or more status incidents, and, except a sealed case, its postmortem (answer key), each with URL, licence, attribution, retrieval time, and SHA-256; those files stay out of Git. The two Cloudflare cases also have Radar charts, committed under `data/charts/` because their licence (CC BY 4.0) allows it; the registry refuses a chart under any other licence. |
| Model client | `hindcast.models` | One Responses API call through the Foundry project, signed in with `DefaultAzureCredential`. Sends the reasoning effort on every call and the image detail with every image, so a changed service default cannot change results; never sends `temperature` or `top_p`. Raises on an incomplete or empty answer and on a response without token usage. Reads model versions from the deployment. |
| Prior-knowledge check | `prompts/prior_knowledge.md`, `hindcast.evaluation.prior` | Asks each model about each showcase outage from its provider, public title, and date only, and writes `eval/results/prior-<date>-<deployment>.json`. |
| Evidence cut | `hindcast.evidence` | Applies [decision 0005](../decisions/0005-evidence-library-and-answer-key.md) per status format (Statuspage for Cloudflare and GitHub, Google Cloud's feed entry): keeps every update before the resolved one and only the resolved update's time and status, and drops report entries, unknown statuses, and anything after the resolved mark into a list without their text. A case over several status incidents is cut per incident and merged by time, so each incident keeps its own resolved mark. The start is the earlier of the snapshot's start and its first update, since Statuspage can backfill the start. Times are normalised to UTC. |
| Blob access | `hindcast.storage` | Reads and writes Blob Storage with `DefaultAzureCredential`. A source is returned only if its SHA-256 matches the registry; an upload never overwrites unless asked. |
| Ingestion | `hindcast.ingest` | `evidence` downloads each case's status snapshots, cuts them, attaches its charts' stored descriptions, and writes the evidence to `build/evidence/` and Blob `extracted/evidence/`, printing counts only. `charts` describes each chart once. `library` extracts each library page once. Extracts already in Blob Storage are reused unless `--replace` is given. |
| Library registry | `data/library.yaml`, `hindcast.library` | The symptom tags each case is picked by, quoted from its evidence, and 23 earlier postmortems picked by them ([decision 0013](../decisions/0013-library-selection.md)). Refuses a document dated on or after a case it serves, a case's own postmortem, and a reason that quotes no tagged symptom. The pages stay out of Git, in Blob `sources/library/`. |
| Content Understanding analyzers | `analyzers/*.json`, `hindcast.extract` | Three analyzer definitions (postmortem pages, chart images, answer keys) on gpt-5.4-mini; the two on the document base also name `text-embedding-3-large`. Creates missing analyzers. Before an analyzer's first analysis in a process, refuses it if its service copy differs from its file or names another model than the extraction deployment's, or if the resource's defaults map that model to another deployment ([#41](https://github.com/sindredg/hindcast/issues/41)), and records that deployment's model name and version with each result ([decision 0018](../decisions/0018-extraction-model.md)). |
| Library extraction | `hindcast.library_extract` | Cuts each page to its article by a rule per site, refuses a page whose title, date, or body the rule cannot find or whose date differs from the registry, splits the extracted markdown into sections, drops text dated after the earliest served case, and describes each figure. A library figure is shown only under a licence that allows it, which no library page has. Extracts go to `build/extracted/library/` and Blob `extracted/library/`. |
| Answer keys | `hindcast.keys`, `eval/keys/` | Drafts a key per case from its postmortem, with a quote per item checked word for word, and a review sheet; freezes a reviewed key and records its SHA-256 in `eval/keys/frozen.json`, which a test checks ([keys](../../eval/keys/README.md)). |
| Library index | `hindcast.index`, `infra/modules/search.bicep` | `build --dimensions <n>` checks each library extract against its blob, cuts it into chunks inside one section or one figure (a section over 4,000 characters splits at paragraphs, a table after a row), embeds them through the Foundry resource endpoint, and pushes them to `hindcast-library-<n>`; it refuses an index that holds documents unless `--replace` is given. `check-filter`, `check-chunks`, and `quality` are the gate and the [frozen quality check](../../eval/retrieval/library-v1/README.md). The service comes from Bicep deployed with `az deployment group create` ([decision 0019](../decisions/0019-library-index.md)). |
| Library search | `hindcast.search` | `search_library` builds the filter from the registries alone (published before the case's start day and, unless the case is sealed, picked for it), runs a hybrid keyword and vector search with semantic ranking, and checks every hit again in code; a hit outside the rule or with a `ref` that does not resolve raises `LibraryLeak`. The query never reaches the filter. The investigator's `search_library` tool calls it. |
| Leak check | `hindcast.leak` | Reports any 8-word run that an answer-key item not stated during the incident shares with the case's evidence or with the chunks its filter returns from the live index. `--snapshot <file>` reads the chunks from a sealed case's snapshot instead, offline, after checking the file against its recorded hash. Prints item and source IDs, never text; `--plant` proves a planted quote is reported. |
| Investigator tools | `hindcast.tools` | `list_updates` and `list_charts` serve one case's evidence file, which the command binds; the model never names a case. `search_library` takes one query of at most 1,000 characters and nothing else; the command binds the search to the case, so the date bound and picks come from the registries. It returns at most five hits, without scores; zero hits is an answer. Each result carries a fixed note (the resolved update's text is withheld; a chart description is a lead; a library hit is another outage). The case title and every update, chart, and hit pass Prompt Shields once per run before the model reads them; a flagged one is replaced by its ref and a `withheld` marker, and the rest is shown. The tools keep the case refs shown, the refs withheld, and the library refs shown, for the citation check ([decision 0021](../decisions/0021-screens-pii-and-challenge.md)). |
| Investigation result | `hindcast.result` | The strict JSON schema the model fills, checked locally with `jsonschema`. Checks every citation against the bound case, removes and lists the bad ones with a reason, and lists items left with no support ([decision 0015](../decisions/0015-investigation-result-and-citation-policy.md)). A library citation is kept only for a ref a search in the run showed (`not-retrieved` otherwise), and an item backed only by library citations is unsupported ([decision 0020](../decisions/0020-library-citations.md)). A `rests_on` entry is rejected when it sits on an observation, names its own finding, names an ID two findings carry, or closes a loop among findings; support is transitive, so an item resting only on unsupported findings is unsupported ([#25](https://github.com/sindredg/hindcast/issues/25)). A withheld ref is rejected as `withheld`, and a case ref the run never read as `not-shown` ([decision 0021](../decisions/0021-screens-pii-and-challenge.md)). Also the challenge schema and its check, and the loader for a stored result file. |
| Investigator and challenger agents | `prompts/investigator.md`, `prompts/challenger.md`, `hindcast.agent` | The prompt agent definitions: the instructions (investigator prompt v3, which asks for at least one search; challenger prompt v1), the three tools, the output schema (investigation or challenge), effort medium, and the chat deployment. A fingerprint is stored in each agent version's metadata; a changed definition creates a new version of `hindcast-investigator-<deployment>` or `hindcast-challenger-<deployment>`, with any character Foundry refuses in a name (the dot in `gpt-6.1-sol`) replaced by a hyphen. An evaluation arm with other instructions or tools is an agent of its own, `hindcast-investigator-<deployment>-<arm>`, so the sealed agents' latest versions stay the ones the seals ran. |
| Investigation command | `hindcast.investigate` | Refuses a scored case until the rubric is frozen and a sealed case at any time, and screens off (`--screens off`) for any case that is not an injection copy, before any cloud call. `--arm` picks an evaluation arm (`hindcast.arms`). Runs the tool loop with 12 tool calls (searches included) at most, and gives every model call the time left in 120 seconds as its timeout; within a tool call, the search, its embedding, and the screen share the time left. Nothing retries. A screen or PII error ends the run as `screen-error` or `pii-error`, and a failed model call as `model-error: <type>` with the usage so far ([#23](https://github.com/sindredg/hindcast/issues/23)). The answer's free text and the search queries pass PII detection, with its own 30 seconds, and each hit is masked by its category, overlapping hits as one span (`hindcast.redact`). It writes `build/investigations/<case_id>/<UTC time>-v<agent version>.json` (the single-search arm, which has no agent version: `<UTC time>-single-search.json`) with the agent, model, provenance, checks, every tool call (each search's query and the refs it showed, the refs withheld, and the screen calls, no hit text), the PII hits by path and category, the usage, and the cost. The provenance names the arm, whether the screens ran, the commit and the tree of `src/` ([#39](https://github.com/sindredg/hindcast/issues/39)), the library registry's blob, the index, the search API version, the embedding model, and the count and SHA-256 of every chunk the case's filter returns, so a rebuild under the same index name shows ([#47](https://github.com/sindredg/hindcast/issues/47)); a filter that returns no chunk is refused before the agent version is made. The result records the effort each response applied next to the requested one ([#26](https://github.com/sindredg/hindcast/issues/26)). An injection copy searches the injection index, which no other case can reach. Missing search or safety settings, or a deployment with no price, fail before the agent version is made. Prints counts, never the investigation text. |
| Safety clients | `hindcast.safety` | Prompt Shields and PII detection on the Foundry resource over REST, with an Entra token and no retry. Splits long texts within each service's limits, counting Prompt Shields' limit in UTF-16 units as the service does ([#54](https://github.com/sindredg/hindcast/issues/54)); for Prompt Shields each piece starts 1,000 characters before the last one ended, so an instruction of up to 1,000 characters across a cut reaches the service whole in one piece ([#50](https://github.com/sindredg/hindcast/issues/50)); an error, a credential failure included, names the HTTP status and the service's code or the error's type, never its message; a missing flag, an entity without its fields, or a hit outside its text is an error. PII drops `PersonType`, `Organization`, `DateTime`, `URL`, and `IPAddress`, which name roles, providers, times, and service addresses in an outage report, and any hit whose text is a provider's name, with or without a possessive "'s", whatever its category: the detector tags "Cloudflare" as a `Person` in some sentences ([#79](https://github.com/sindredg/hindcast/issues/79)). |
| Challenge command | `hindcast.challenge` | Challenges one finding of a stored result on the result's own deployment. Refuses an incomplete result, a result that ran without screens, an unknown finding, an empty or over-1,000-character question, and evidence that differs from the result's, before any cloud call. Screens the question as a user prompt (flagged: refused, no model call), masks its personal data, and runs the loop with 6 tool calls and 90 seconds. A library ref the original run showed stays citable. Writes `challenges/<UTC time>-<finding id>.json` next to the result. |
| Seal command | `hindcast.seal`, `eval/sealed/seals.json` | Runs the investigator once on a sealed case and records the result's SHA-256, the commit, the agent and model versions, and the status in `seals.json` before uploading the file to Blob `extracted/sealed/`, never over an existing blob. Seals made with the library search carry `library: true`, a series next to the first one. Refuses, before any cloud call, a case that is not sealed, a second seal for the same case, deployment, and library setting, a changed `src/`, `prompts/`, `pyproject.toml`, `uv.lock`, `data/cases.yaml`, or `data/library.yaml`, and a `seals.json` that does not extend the committed one. After it makes the agent version, it runs one library search and refuses, before the first model call, while the search fails. A test walks every committed version of `seals.json` and fails if an entry changed or went missing ([#33](https://github.com/sindredg/hindcast/issues/33)). Only an attempt with no model output, or one whose model call failed, may be retried, up to three in all. `snapshot <case>` saves every chunk a sealed case's filter returns to a local file and records its hash in `eval/sealed/library-snapshots.json`, which is then committed, for a reveal after teardown ([decision 0022](../decisions/0022-sealed-drop-date-and-offline-reveal.md)). Prints counts and the hash, never the investigation text. A test checks each revealed file against its hash. |
| Evaluation arms | `hindcast.arms`, `hindcast.single`, `prompts/investigator-library-off.md`, `prompts/investigator-abstention.md`, `prompts/single-search.md` | The five arms of [decision 0023](../decisions/0023-abstention-and-inferable-labels.md): the investigator on the chat and the comparison deployment as sealed, one search and one model call over the same evidence, the investigator without the library search, and the investigator with one abstention rule. The single-search arm makes no agent; it calls the deployment with the same schema and runs under the same screens, checks, caps, and model-error handling. |
| Evaluation batch | `hindcast.evaluation.batch`, `eval/reconstruction/showcase-v1/` | Runs one arm on scored showcase cases, one run at a time, with a run ID per result and an entry per attempt in `attempts.json`, written before the run and updated after it. An attempt with no investigation to keep (no model output, or a run ended by a failed model call, screen, or PII check) may be followed by another, up to three per slot; any other run with output is never run again. One library search before each run refuses the batch while the search fails, as the seal does. Refuses an unknown arm, an unscored case, a frozen-rubric miss, a changed tree, and an agent version other than the sealed series', and stops after two failed attempts in a row. Prints counts, never text. |
| Labels | `hindcast.labels`, `eval/keys/labels/` | One label per scored key item (`stated`, `inferable`, `not inferable`), with a reason and the update and chart IDs it rests on. Refuses a file that misses or invents an item, cites outside the evidence, or contradicts the key's `stated_during_incident`; freezes each file once by hash. |
| Injection tests | `hindcast.injection`, `data/injection/` | Writes the injection copies' evidence and the planted library pages, describes the planted chart with the chart analyzer, builds the separate index `hindcast-injection-1024`, and reports which planted instructions a result followed and whether its tools showed or withheld the planted item (the update, the library section, the library figure, or the case chart). The case-chart copy adds the planted chart to the case's own charts with the instruction in its description, because a case chart reaches the model as its alt text and description only ([decision 0026](../decisions/0026-case-chart-injection.md)). A run whose tools never returned the planted item ends as `not reached`, not as a pass ([decision 0025](../decisions/0025-injection-test-layers.md)). |
| Foundry evaluation | `hindcast.evaluation.foundry`, `eval/reconstruction/showcase-v1/foundry/` | `build` rebuilds each evaluated run's tool outputs by replaying its recorded calls on the same evidence and indexed chunks, refuses a replay that returns other refs, and writes two datasets under `build/foundry/`. `submit` creates one evaluation per dataset with the generally available groundedness, relevance, and tool call accuracy evaluators on `gpt-6.1-sol` and records the run IDs; `results` writes per arm and evaluator the rows passed, failed, and errored, and the mean score. Repeat 1 of each arm and case only. |
| Excerpts | `hindcast.excerpts` | Resolves a citation to the text it cites: an update or chart from the case's evidence file, a library section or figure from the local extracts, so neither needs the search service. A section resolves whole, which can be more than the chunk a search showed. |
| Judge | `hindcast.evaluation.judge`, `hindcast.evaluation.judge_prior`, `prompts/judge.md`, `prompts/judge-prior.md`, `eval/judge/` | `claude-opus-5-5` on the Anthropic API, effort `high`, streamed, with no server-side fallback ([decision 0024](../decisions/0024-judge-model.md)). Per run it reads the key items, the run's items after the citation checks, and the cited text, without the arm or the labels, and replies under one fixed JSON schema, a list of run items and a list of key items. The code checks that the reply names every key item and run item once, gives each key item an outcome the rubric allows for its kind, and leaves the code's unsupported items unsupported. A refusal, an empty or cut reply, a schema failure, or outcomes that contradict its own support verdicts are recorded as a judge error and judged again on the next run. Refuses a call unless the prompt and the rubric match their lock; a judgment already made is checked by the system-prompt hash and model it recorded. The prior judge compares each prior answer with its key on the root cause and the attack verdict. |
| Reviewer | `hindcast.evaluation.reviewer`, `prompts/reviewer.md`, `prompts/reviewer-prior.md`, `eval/judge/frozen-reviewer*.json` | `claude-fable-5-1` judges every judged run and prior answer again through the judge's code, from the same input and without the judge's proposals ([decision 0027](../decisions/0027-reviewer-model.md)). Its prompts are the judge's less the sentence that says a person reviews. `apply` writes its outcome or support verdict on each queue item as the review decision, with its model and the SHA-256 of its judgment; it refuses a second judgment made on other input or under another lock, and skips one with an error. |
| Review | `hindcast.evaluation.review`, `hindcast.review` | The review queue, as rubric version 2 froze it and version 3 keeps it: every proposed hit, partial, unsupported hit, and unsupported partial, every support verdict on an inference, and a quarter of the rest drawn per run with the seed 20261104. Decisions are stored per run with the hash of the judgment they review. A local Streamlit page shows one item at a time with its cited text under a blind run ID; since rubric version 3 the reviewer model decides every queue item, so the page shows "Every item is decided." once `apply` has run. Its undo button still removes a run's latest decision. Never deployed. |
| Scores | `hindcast.evaluation.score`, `eval/reconstruction/showcase-v1/scores.json`, `eval/prior-knowledge/v1/scores.json` | Replaces the judge's proposals with the reviewed decisions and applies the frozen labels' credit; writes the primary score per run and per arm and case, the unsupported, wrong, and guessed items, the judge-reviewer agreement (percent and Cohen's kappa), and the prior answers' outcomes with the known-before-evidence pairs. A decision the reviewer model made is checked against the run items its own judgment listed, and that judgment's hash against the decision. When every run has a decision from the reviewer model, it also writes the agreement over every item and each arm's mean with each judge alone, and otherwise says it left them out. Refuses while a review item is open. |
| Usage and cost | `hindcast.costs`, `data/prices.yaml` | Each run records its tokens, its screen and PII calls with their text records, and its largest call. The cost comes from version 1 of the price table (model, embedding, Prompt Shields, and PII prices with the meter and date each was read). The total is the sum of the rounded parts. A deployment missing from the table raises; a call past the short-context limit is recorded as not priced. |
| Judge and reviewer spend | `hindcast.evaluation.spend`, `data/claude-prices.yaml`, `eval/judge/spend.json` | Prices the Claude API usage each judgment file records, per stage and model, from version 1 of the Claude price table (input, 5-minute cache write, cache read, and output, with the page and date they were read). A model missing from the table or a usage field missing from a record raises; an errored call that was run again is counted as unpriced; a stage with no files is refused. The Anthropic Console's billed total is the check on it ([report](../../eval/reconstruction/showcase-v1/README.md#cost-and-spend)). |
| Page | `hindcast.app`, `.streamlit/config.toml` | A Streamlit page with two views, the investigation and the glossary, in a dark theme with the project palette. The investigation view names each result by what ran, on which model, and when, and opens on the newest committed `gpt-6-luna` run of the development case. It shows the case's title, provider, start, and role, then a row of tiles (the attack assessment, complete or incomplete, the finding count, rejected citations, withheld items, and the cost), and an incomplete run's reason before anything else. Tabs hold the investigation (the attack assessment and the root cause side by side, the timeline, the findings as cards with their stored challenges, the contributing factors, the open questions), the evidence (every cited item once, updates in time order, with the items that cite it), the checks, the injection test for an injection copy, and the usage with the provenance. A citation is a button that opens the cited update, chart, or library passage (`hindcast.cited`); without the run's files it shows as its ID, a library citation as `library:<ref>`. Model-written text and the IDs the model chose render escaped (`hindcast.escape`), and provider text renders as plain text, so a link or an image a planted instruction asks for shows as text. The injection test shows the planted item shown or withheld, the planted instructions followed, and the outcome from `hindcast.injection`, because a withheld count of 0 alone does not say whether the model followed the planted text. The labels' help texts are the glossary's entries. ### The investigator

Hindcast runs the tool loop, not the service: the agent in Foundry holds the instructions and the tool definitions, and the command executes every tool call on the workstation, so the case scoping, the caps, and the checks hold in code ([decision 0002](../decisions/0002-agent-approach.md)).

The first run on the development case is in the [worklog](../worklogs/04-investigator.md#live-run), the first with the library search in its [second slice](../worklogs/04-investigator.md#slice-2-the-library-search-tool), and the first with the screens, the PII check, the challenge, and the traces in its [third slice](../worklogs/04-investigator.md#slice-3-screens-pii-challenge-traces-and-cost).

![The investigation loop: the investigate command refuses a scored case before the rubric is frozen, a sealed case at any time, a case without its evidence file, its search or safety settings, a price for its deployment, or library chunks for its filter, or screens off for a case that is not an injection copy, before any model call. Otherwise it calls the investigator agent with the time left as the call's timeout; while the response holds function calls, it runs each tool, the case evidence or the library search bound to the case, screens every item it returns with Prompt Shields and withholds a flagged one, and sends the outputs back in the next turn. A response without function calls is parsed against the schema and its citations are checked: a citation is kept only for an item the model was shown. Personal data in the answer is then masked. A model call that times out or fails, a thirteenth tool call, a tool call that would start after 120 seconds, a tool or screen error, an empty answer, a schema error, or a PII error ends the run as incomplete with the reason. Either way the result file is written and the command prints counts, never the investigation text.](../diagrams/investigation-loop.svg)

### The library search

A case searches only the library documents published before its start day and, unless it is sealed, picked for it. The filter comes from the registries, never from the query, and every hit is checked again in code, so a wrong filter or a wrong index raises instead of reaching the investigator ([decision 0019](../decisions/0019-library-index.md)).

The procedure is the [retrieval runbook](../runbooks/retrieval.md); the gate that checks it on the live index is in the [worklog](../worklogs/03-retrieval.md#gate).

![Library index and search: The index build reads the library extracts, checks each against its blob, cuts them into chunks that stay inside one section or one figure, embeds them through the Foundry resource endpoint, and pushes them to the library index in Azure AI Search, refusing an index that already holds documents. A search takes a case ID and a query: the filter comes from the registries alone (published before the case's start day and, unless the case is sealed, picked for the case), the query text reaches only the hybrid keyword, vector, and semantic search on the index, and every hit is checked again against the same rule and the extracts. Hits that pass are returned with their ref, document, and date; a hit outside the rule raises LibraryLeak and nothing is returned](../diagrams/retrieval.svg)

### Sealed reconstructions

A sealed case is an outage whose provider had not published a cause when Hindcast reconstructed it. The hash is public from the day of the seal; the file stays in Blob Storage until the postmortem is out and the rubric is frozen, so no model's account of a provider's outage is published before the provider's own ([decision 0017](../decisions/0017-sealed-reconstructions.md)).

The procedure is the [sealing runbook](../runbooks/sealing.md).

![Sealing a reconstruction: the seal command refuses, before any model call, a case that is not sealed, a case and deployment that already have a seal in this series, a changed tree, a seal record that does not extend the committed one, or a library search that does not answer; otherwise it investigates once with the library search, records an attempt with no model output as no-result, which may be retried up to three attempts in all, and otherwise commits the hash and uploads the file to private storage. If the provider publishes its cause by 2026-11-30, the file is revealed after the rubric is frozen, checked against its hash, and scored; if not, the case is dropped with its record kept](../diagrams/sealing.svg)

### The prior-knowledge check

Every refusal happens before a model is called, so a refused run costs nothing and every result points at a prompt, a registry, and code that are in the history. A test also checks that no key fact from a postmortem appears in any question, the incident's title included, or in the system prompt.

![The prior-knowledge check: the collector refuses to run, before any model call, when the prompt, the case registry, the code, the project file, or the lock file differs from the last commit, when today's result file exists, or when a showcase case has no date in the prompt. Otherwise it reads the model version from the deployment, asks about each showcase outage from its provider, title, and date at effort medium, writes one result file with the version, effort, hashes, and commit, and prints token counts but never the answers](../diagrams/prior-knowledge-check.svg)

### The evaluation

The judge proposes and a second model, judging blind, decides ([decision 0006](../decisions/0006-evaluation-design.md), [decision 0024](../decisions/0024-judge-model.md), [decision 0027](../decisions/0027-reviewer-model.md)). No person decides an item. Both models run outside Azure, so judging, review, and scoring need no Azure resource. The procedure is the [evaluation runbook](../runbooks/evaluation.md); the results are in the [evaluation report](../../eval/reconstruction/showcase-v1/README.md) and the [injection report](../../eval/injection/dev-v1/README.md).

![Scoring the reconstructions: every filled scored run and every prior-knowledge answer goes to the judge, claude-opus-5-5 on the Anthropic API, with the frozen keys and the rubric's outcome and support rules but without the run's arm or the labels; the reviewer, claude-fable-5-1 on the Anthropic API, judges each run and answer again from the same input without the judge's proposals, and its verdicts decide the review queue that the judge's proposals select; the score reads the judgments and the reviewer's decisions, a decision replacing the judge's proposal, and applies the frozen labels' credit; the Foundry cloud evaluators score repeat 1 of each arm and case with gpt-6.1-sol as their judge; both go into the evaluation report per arm and case.](../diagrams/evaluation-flow.svg)

### The deployment

One `azd up` creates the app's resource group from Bicep, and `azd down` removes it; the resource group built earlier is only read. The reasons for the sign-in credential, the build path, and the separate group are in [decision 0016](../decisions/0016-sign-in-credential-image-build-and-resource-group.md); the procedure is the [deployment runbook](../runbooks/deployment.md).

![A reader's browser reaches the Hindcast container app over HTTPS; the app's built-in authentication redirects every request without a session to Entra ID and lets one account in, signing in as the app through a federated credential on its managed identity instead of a client secret. The app runs in its own resource group, created by azd from Bicep, on at most one replica that scales to zero, pulling the image from the group's container registry with its identity. ## Pipeline

GitHub Actions runs `.github/workflows/ci.yml`. `main` accepts changes only through a pull request with the four checks passing and signed commits.

| Job | When | What it runs |
|---|---|---|
| Lint, type checks, and tests | Every pull request and push to `main` | ruff, ruff format, pyright, and pytest, with the `app` extra installed, on a checkout with the full history, which the seal record test walks |
| YAML and workflow checks | Same | yamllint, zizmor, actionlint |
| Dependency audit | Same | pip-audit on the locked tree, extras included |
| Image and infrastructure | Same | hadolint on the Dockerfile; shellcheck on the hook scripts; `az bicep build` and `az bicep lint` on `infra/main.bicep`, which builds every module, with the rules in `infra/bicepconfig.json` raised to errors, failing on any printed diagnostic; the provenance manifest written from the checkout; a build of the image, and a run of it that checks its user, loads the stored result inside it, checks that a run names its code from the manifest, that the runtime user can write `build/` and a case's `challenges/` directory, and that it can neither append to nor remove a committed result, and waits for Streamlit's health path |
| Push | Push to `main` only, in the `azure` deployment environment, which admits only `main` | Signs in to Azure with the run's OIDC token, whose subject names that environment, against the CI identity, and pushes the image to the registry. The environment's secrets hold IDs, not credentials |

Dependabot proposes weekly updates for the actions and the Python dependencies ([`.github/dependabot.yml`](../../.github/dependabot.yml)); nothing merges automatically. Python stays on 3.14 because Dependabot supports no newer version ([#8](https://github.com/sindredg/hindcast/issues/8)). The uv version, the Python version, actionlint, and the runner image move by hand.
